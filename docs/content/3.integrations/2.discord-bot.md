The Discord bot in
[`integrations/discord-bot`](https://github.com/Niki2k1/mcsm/tree/main/integrations/discord-bot)
lets members of your Discord server whitelist themselves:

1. A moderator runs `/setup-rules`; the bot posts your rules with an
   **Accept rules & get whitelisted** button.
2. A member clicks the button and enters their Minecraft username.
3. MCSM whitelists the account right away and the bot confirms privately —
   optionally giving the member a "whitelisted" role.

Each Discord member can whitelist **one** account per server, and an account
can only be claimed by one member. This is enforced by MCSM through
[one-time claims](/integrations/public-api#one-time-claims), not by the bot, so
it survives bot restarts and reinstalls. Moderators see all claims on the
server's **Players** tab and can release one to let a member pick a different
account.

## Commands

| Command | Who | What |
| ------- | --- | ---- |
| `/setup-rules [server]` | Manage Server | Posts the rules and the claim button in the current channel. |
| `/whitelist list [server]` | Manage Server | Shows the whitelist (only to you). |
| `/mcstatus [server]` | Everyone | Whether the server is online and who is playing. |

## Set it up

1. In MCSM, create a [personal access token](/integrations/public-api#create-a-token)
   with the **Read** and **Whitelist** scopes, limited to your server.
   *Whitelist* can't run console commands or stop the server, so the bot's
   token can do nothing beyond managing the whitelist.
2. Create a Discord application and bot, then invite it with the `bot` and
   `applications.commands` scopes and the *Send Messages* and *Embed Links*
   permissions (plus *Manage Roles* for the optional role).
3. Write your rules as Markdown — a leading `# Heading` becomes the title.
4. Run the bot (single Go binary or Docker image) with:

| Variable | Required | Description |
| -------- | -------- | ----------- |
| `DISCORD_TOKEN` | yes | Bot token. |
| `MCSM_URL` | yes | MCSM's base URL. |
| `MCSM_API_TOKEN` | yes | The `mcsm_pat_…` token. |
| `RULES_FILE` | yes | Path to the rules Markdown file (re-read on every `/setup-rules`). |
| `MCSM_SERVER_ID` | no | Default server, e.g. `mc-survival`. |
| `DISCORD_GUILD_ID` | no | Register commands in one Discord server for instant availability. |
| `WHITELISTED_ROLE_ID` | no | Role given after a successful claim. |

The bot's README has build and Docker instructions.
