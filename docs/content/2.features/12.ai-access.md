MCSM runs a [Model Context Protocol](https://modelcontextprotocol.io) server at
`/mcp`. Connect an AI assistant to it and ask things like *"Is anyone online on
the survival server?"*, *"Restart the modpack server and tell me when it's
up"* or *"Back up the creative world before I update it"*.

## Connect a client

Open **AI access** in the user menu and copy the endpoint, or add it directly:

```bash
claude mcp add --transport http mcsm https://mcsm.example.com/mcp
```

The first time the client connects, it opens MCSM in your browser. Sign in,
check what the app asks for and click **Allow**. Clients that support remote
MCP servers with OAuth (Claude, Claude Code, Cursor, VS Code, ...) do this on
their own: they register themselves and refresh their access in the
background.

You can disconnect an app at any time under **AI access → Connected apps**.

## Personal access tokens

For scripts or clients that can't sign in through a browser, create a token
under **AI access → Personal access tokens** and send it as a bearer token:

```bash
claude mcp add --transport http mcsm https://mcsm.example.com/mcp \
  --header "Authorization: Bearer mcsm_pat_..."
```

The token is shown once; MCSM only stores a hash of it. Delete it to revoke
access. When creating it you can also:

- **limit it to some servers** — left empty, it covers every server you can
  access, including ones created later;
- **let it expire** after 30 days, 90 days or a year.

The same tokens work for the [public API](/integrations/public-api), e.g. for
the [Discord bot](/integrations/discord-bot).

## What an assistant can do

Every connection acts as **you**: it only sees the servers you can see (or
the ones a personal access token is limited to) and
never gets more than your [role](/features/authentication#share-single-servers)
allows on each server. On top of that, a connection only gets the scopes you
approved:

| Scope | Role needed | Tools |
| --- | --- | --- |
| **Read** | Viewer | List servers, server details and resource usage, online players, activity |
| **Operate** | Operator | Start/stop/restart, recent console output, console commands, op/whitelist/kick |
| **Manage** | Manager | List and create backups |
| **Whitelist** | Operator | Add and remove whitelisted players — no console, power or op (meant for bots) |

Player changes behave like the **Players** tab: they go through RCON on a
running server, edit `whitelist.json` / `ops.json` on a stopped one (applied
on the next start) and are refused while the server is still starting.

::warning
Console commands run with full operator rights on the server. Only grant
**Operate** to assistants you trust, and keep an eye on what they want to run —
most clients ask before calling a tool that changes something.
::

## Behind a reverse proxy

MCP clients check that the OAuth issuer matches the URL they connected to.
MCSM derives it from the request and honors `X-Forwarded-Host` /
`X-Forwarded-Proto`. If your proxy doesn't send those, set `NUXT_APP_URL` to
MCSM's public URL.
